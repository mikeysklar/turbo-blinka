Turbo on Blinka

Plain Python fixes go to Blinka. Compiling is for your own code on a Pi.

What we learned

  • Blinka runs on regular Python, so turbo's board compiler does not apply.
  • Find wasted work first: three plain Python fixes gave 2x to 241x.
  • Types make the speed: Cython without types is 1.4x, with types 119x.
  • A compiled file is tied to CPU, Python version and C library, so it stays out of Blinka.
  • Numba needs no build, but starts slowly on a Zero.

The CLI

One project folder, the same one that runs on a CircuitPython board.

Your code, marked once

from turbo import turbo

@turbo.viper
def mandel_row(out: ptr8, width: int,
               dx: int, cy: int,
               max_iter: int):
    ...

Run it three ways

python3 code.py               # source

turbo build --target cpython  # Cython
python3 code.py               # uses the .so

TURBO=numba python3 code.py   # Numba

turbo build reads the function, types every integer loop variable, and names any it could not type. 173 tests. Repo: turbo-cli.

Issues we hit

IssueWhat it means
Cython with no types: 1.4xOne missed loop variable stays slow, silently. The CLI reports them.
A built file is tied to the machineCPU, Python version, glibc. A Pi build will not load on a minimal Linux.
No compiler on minimal platformsWhy compiled code stays out of Blinka itself.
Numba start-up on a Zero 2 W10 s first run, about 4 s after, against 44 ms from source.
Numba cannot compile everythingObjects and casts fail. The shim falls back to source with one line.
numpyNeeds a rewrite and was 10x to 20x behind. Dropped.
